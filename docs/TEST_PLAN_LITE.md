## 2. 制定原则

本方案面向测试开发求职，不以继续开发复杂 Agent 为目标。由于可投入时间有限，只保留能够形成简历成果和面试案例的核心内容：

1. 建立可复现、与正式数据隔离的测试环境；
2. 对文件上传、文档管理、Chat 和 SSE 进行核心 API 自动化测试；
3. 使用现有评测程序量化 RAG 检索质量；
4. 使用少量代表性问题验证 Agent 路由是否正确；
5. 验证 1～2 个高价值的可靠性或安全风险；
6. 输出包含测试结果、缺陷和质量指标的测试报告。

测试应优先保证“有真实执行结果、有明确缺陷、有量化指标”，不追求测试范围面面俱到。

## 3. 测试目标

- 项目能在独立测试环境中稳定运行自动化测试；
- PDF、CSV、Excel 上传和文档管理接口符合预期；
- Chat 和 SSE 流式接口在正常及异常情况下行为正确；
- RAG 能检索到正确研报和相关证据；
- Agent 能针对研报、数据、实时信息选择正确工具；
- 本地没有答案时，系统不会编造内容或错误联网；
- 非法文件 ID 不会造成错误文件匹配或删除；
- 索引重建失败时，旧索引仍然可用。

1. 正常 Chat 请求；

3. 模型异常或超时。

SSE 重点检查：


- `start` 和 `end` 只出现一次；
- `session_id` 前后一致；
- Token 没有乱码和明显重复；
- `end.content` 与 Token 拼接结果基本一致；
- 模型异常时返回受控 `error`；
- 异常响应不保存为空白成功回答。

- 人工抽查 5～10 条复杂回答。

### 7.7 两个高价值风险

#### 风险一：非法文件 ID

动态验证已完成。初始实现将未经格式校验的 `file_id` 拼入 glob 模式，`file_id=*` 能删除多份不相关测试文件并触发向量删除，已登记为 `RA-API-001`。验证输入包括：

- `file_id=*`；
- `file_id=../`；
- 非 UUID 字符串；
- 一个请求是否可能匹配多份文件。

修复方式：文档查询、删除和重建接口统一使用 UUID 路径参数，并在任何文件匹配或向量操作前拒绝非法值。

完成结果：4 个针对性测试通过；通配符、路径穿越形式及非 UUID 字符串均返回 422，测试文件和向量保持不变。

#### 风险二：重建索引失败

测试步骤：

1. 准备一份已经可以正常检索的报告；
2. 重建索引时 Mock Embedding 或 Chroma 写入失败；
3. 重建结束后再次查询旧内容；
4. 检查旧索引是否仍然存在。

初始验证结果：新 PDF 解析失败前，旧索引已被删除，旧向量块从 1 条变为 0 条，已登记为 `RA-API-002`。

修复方式：先完成解析、分块和新向量计算，再替换旧记录；写入失败时清理部分新记录并从快照恢复旧索引。

完成结果：解析失败、空分块、嵌入失败、向量写入失败及回滚保护等 6 个针对性实例通过，重建失败时旧索引仍可使用。
